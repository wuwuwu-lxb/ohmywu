# OhMyWu 使用引导

> 最后更新：2026-05-20

## 1. 项目定位

OhMyWu 是一个本地优先的桌面 Agent 工作台，重点不是堆更多入口，而是把下面几件事做扎实：

- 对话可持续
- 工具调用可见
- 执行权限可控
- 知识可沉淀
- Action / Skill / Agent 能继续扩展

## 2. 首次启动

### 环境要求

- Node.js
- Rust
- Tauri 2

### 本地运行

```bash
npm install
npm run tauri dev
```

### 基础检查

```bash
npm run build
cargo check
```

## 3. 页面说明

### 对话

- 用来发起任务、查看回复和运行过程
- 每条回复下方都可以展开 Runtime 和工具调用
- 运行时会展示耗时、工具状态、记忆召回等信息

### Agent 管理

- 管理多个 Agent 档案
- 可编辑人格、角色、记忆范围和召回策略
- 当前阶段以主 Agent 配置管理为主，多 Agent 编排仍在继续完善

### 知识库

- 管理知识条目、分类和图谱视图
- 适合沉淀长期记忆、操作规范、项目事实和个人偏好
- 记忆候选支持手动确认后写入，避免自动污染

### 模型设置

- 管理多套模型配置
- 支持手动填写 Provider / Endpoint / Model
- 支持拉取模型列表
- 支持连接测试
- 支持指定当前启用模型

### 原子化能力

- 查看底层 capability 注册情况
- 区分内置能力和可扩展能力
- 这层是 Action 和 Agent 真正调用的执行单元

### Action 注册

- 查看系统内 Action
- 后续会以“AI 生成 / AI 修改，人来启用、测试、删除”为主流程
- 兼容 `SKILL.md` 生态，支持 Skill 转 Action

### 审计日志

- 查看关键执行记录
- 用于回溯高风险操作、权限决策和任务链路

### 设置

- `外观`：主题色、纯色背景、图片背景、遮罩、模糊、缩放
- `执行与权限`：策略模式、Agent Mode、权限规则

## 4. 推荐使用顺序

1. 先到 `模型设置` 配好至少一套可用模型。
2. 到 `设置 -> 执行与权限` 选择合适的策略模式。
3. 在 `Agent 管理` 建立适合当前任务的 Agent 档案。
4. 在 `知识库` 录入长期有效的信息，再开始复杂任务。
5. 在 `对话` 中实际运行，并通过 Runtime 检查工具过程。

## 5. 权限模式

### Policy Mode

- `Sandbox`：更保守，写入和高风险命令会先被策略拦下
- `Danger`：允许进入执行阶段，再由具体规则和确认逻辑决定

### Agent Mode

- `plan`：偏分析，只暴露只读工具和 checklist
- `agent`：完整工具集，高风险操作默认需要确认
- `auto`：完整工具集，高风险操作可直接执行

## 6. 知识库建议

- 把稳定事实写进知识库，不要把一次性上下文都塞进去
- 优先存放项目规则、接口约束、运行习惯、常见故障
- 记忆候选建议人工确认，避免把错误推断写成事实

## 7. Action / Skill 方向

当前项目已经具备 Skill 转 Action 的兼容基础。推荐的长期方向是：

- 人负责定义边界、审核结果、启停能力
- AI 负责注册、转译、补全和调整 Action
- 内置能力与内置 Action 不允许误删
- 用户自定义能力和自定义 Action 可以关闭、删除、测试

## 8. 常见排查

### 拉不到模型列表

- 检查 Endpoint 是否正确
- 检查 API Key 是否有效
- 检查当前 Provider 的协议格式是否匹配

### 工具没有执行

- 检查 `设置 -> 执行与权限`
- 看是否被 `Sandbox` 或 `deny` 规则挡住
- 到 Runtime 和审计日志里确认具体拒绝原因

### 背景或主题不符合预期

- 纯色模式下分别调整背景主色和主题色
- 图片模式下可重新提取背景主色
- 模糊、遮罩、缩放都需要配合一起调

## 9. 当前阶段重点

当前更适合做：

- 模型兼容性测试
- 权限和审计体验验证
- 知识库写入与召回链路测试
- Action / Skill 注册链路打磨

当前暂不建议把它当成完全稳定的生产桌面端。
