# OhMyWu v0.26 优化计划

> 最后更新：2026-05-25
> 当前阶段定义：从“可发布预览版”推进到“可长期使用的工作台”

## 1. 这一阶段的核心目标

`v0.25.0` 已经完成了一个重要节点：

- 前端可用
- Agent loop 可跑
- 工具调用可见
- 审计和知识库已有基础闭环
- AppImage / deb / rpm / Arch 包路径已经打通

下一阶段不应该继续优先堆页面，而应该集中解决三件真正影响长期使用的问题：

1. 执行结果不够可信
2. 长对话上下文管理不够稳定
3. Action / 记忆 / Agent 虽然已有雏形，但还没有真正形成高质量执行流

因此，`v0.26` 的主题建议明确为：

## 2. 阶段主题

**可信执行 + 上下文管理 + 轻量工作流**

这意味着本阶段的重点不是“新功能越多越好”，而是：

- 降低幻觉
- 提高长任务稳定性
- 让执行链路更可控
- 把现有 Action / 记忆 / Agent 原型变得真正可用

## 3. 优先级顺序

### P0. 可信执行闭环

这是最高优先级。

当前最危险的问题不是模型慢，而是模型有时会“以为自己执行过了”，或者执行结果没有被足够稳定地回注到后续轮次里，导致：

- 刚拿到的系统信息下一轮就忘
- 工具失败后模型仍然继续假设成功
- 多步任务中间状态不稳

这一阶段需要补的能力：

1. 工具调用状态结构化
   - `pending`
   - `running`
   - `success`
   - `failed`
   - `cancelled`

2. 工具结果摘要化
   - 每个工具执行后产出一份短摘要
   - 摘要单独作为下一轮可引用上下文
   - 大输出不直接整块回灌

3. 执行确认机制
   - 模型只能基于 runtime 真实状态声称“已完成”
   - 禁止把“已请求执行”误判为“已执行成功”

4. 手动中止 / 重试 / 恢复
   - 长任务支持用户中止
   - 失败工具支持重试
   - 同一 turn 保留中间执行轨迹

5. 对话级 runtime 持久化
   - 不只是前端临时展示
   - 要能跨刷新、跨页面、跨重启恢复基本状态

### P1. 上下文管理与压缩

这部分直接决定长任务质量和成本。

现阶段要做的不是“再多传一点上下文”，而是把上下文拆层并可控：

1. 上下文分层
   - system
   - agent profile
   - 最近消息
   - 历史摘要
   - 工具结果摘要
   - 显式记忆注入
   - 显式 action 注入

2. 自动压缩
   - 老消息压缩为阶段摘要
   - 工具大输出变成句柄 + 摘要
   - 历史不再线性全量回放

3. 独立压缩模型
   - 单独配置一个便宜模型
   - 不占主对话模型预算
   - 允许后续独立切换

4. 手动整理入口
   - 用户可手动触发“整理上下文”
   - 用户可查看压缩前后变化

5. 可见性
   - 本轮上下文来自哪里
   - 哪些是记忆
   - 哪些是工具结果
   - 哪些是压缩摘要

### P2. Action 真正进入执行流

现有 Action 页面和 skill 兼容层已经有基础，但还偏“注册表”。

这一阶段要推进到：

1. 对话里显式 `@action`
2. Action 有输入 schema / 输出 schema
3. Action 声明需要哪些原子能力
4. Action 执行过程进入 runtime / audit
5. Action 失败后可回退到普通工具调用

目标不是做复杂 workflow engine，而是让 Action 真正可用。

### P3. 记忆系统质量控制

知识库和记忆候选已经够用，下一步重点应放在质量，而不是更多 UI。

需要补的点：

1. 记忆分层
   - 临时
   - 长期
   - 项目级
   - 用户级

2. 召回原因展示
   - 为什么这条记忆会被召回

3. 去重和冲突检测
   - 写入前检查相似内容
   - 发现矛盾时提示而不是直接写

4. 失效和降权
   - 低质量记忆可归档、禁用、降权

5. 显式 `@memory`
   - 用户可在一轮对话里强制引用某条知识

### P4. 轻量多 Agent

这一步做，但不要太重。

当前建议只做最小可用：

1. 主 Agent
2. coding Agent
3. memory-heavy Agent

这一阶段只支持：

- 对话内切换 active agent
- 主 agent 单跳调用一个副 agent
- 每个 agent 有独立模型和记忆 scope

暂不优先做：

- 复杂并行调度
- 深层嵌套子 agent
- verifier/swarm 式复杂 runtime

## 4. 建议拆分里程碑

### M1. 可信执行

- runtime 状态枚举补全
- 工具结果摘要化
- 成功/失败/取消状态统一
- 中止 / 重试
- turn 级 runtime 持久化

### M2. 上下文管理

- context 分层
- 历史摘要
- 工具输出 parking
- 压缩模型配置
- 手动“整理上下文”

### M3. Action / 记忆进入主链路

- `@action`
- `@memory`
- mention 自动联想
- action 结构化执行
- 记忆召回解释

### M4. 轻量多 Agent

- agent 切换
- 主 / coding / memory-heavy 预设
- 单跳委派
- agent 结果结构化返回

## 5. 当前阶段不优先做的事情

为了避免再次发散，这一阶段明确不优先：

- 大规模前端视觉再重做
- 视频背景等低优先级展示能力
- 复杂定时任务系统
- 多层级 swarm / planner / verifier 编排
- 继续扩充大量新工具页

不是这些以后不做，而是它们不该排在“可信执行”和“上下文管理”前面。

## 6. 验收标准

本阶段结束时，至少应满足：

1. 模型不会再频繁把“未执行”说成“已执行”
2. 长任务可以中止、恢复、重试
3. 工具大输出不会直接炸穿上下文
4. 上下文压缩有独立模型配置
5. 对话里可以显式 `@action` / `@memory`
6. Action 不再只是目录项，而是可执行工作流入口
7. 多 agent 至少支持稳定的单跳委派

## 7. 一句话结论

`v0.26` 不是“再做更多页面”，而是把 OhMyWu 从一个已经能发布的预览版，推进成一个：

- 不容易幻觉
- 能跑长任务
- 能控制上下文成本
- 能真正利用 action / memory / agent 资产

的长期工作台。
