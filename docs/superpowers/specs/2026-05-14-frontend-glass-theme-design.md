# OhMyWu 前端视觉重做设计（SPlayer 风半透明主题）

## 目标

在不改变现有前端业务逻辑的前提下，把 OhMyWu 的整体前端从“功能原型界面”升级为带有 SPlayer 气质的桌面产品界面：半透明、带壁纸、主题色明确、层次统一、可个性化保存。

本次同时修复两个假接入问题：
- 主题 / 强调色目前只存在前端内存，不会持久化
- LLM 测试连接当前没有基于设置页未保存的表单值执行，导致用户看到的是“假测试”

## 非目标

- 不改聊天、会话、agent、action、audit 的业务逻辑
- 不重构 store 数据流
- 不引入新的业务页面
- 不扩展新的后端架构，只补当前设置 / 外观所需字段和命令边界
- 首轮不做自定义上传壁纸，不做资源管理

## 设计方向

采用 **SPlayer 风桌面半透明主题**：
- 桌面级壁纸背景，而不是纯色背景
- 内容区域悬浮在壁纸之上，但重点不是厚重毛玻璃，而是**可调透明度的半透明桌面层**
- 主题色负责高亮、选中态、输入焦点和按钮
- 整个前端统一成一套柔和透明、深色、偏音乐播放器式的视觉语言
- 用户可以切换壁纸，也可以直接调节主界面透明度

用户最应该记住的点是：**这不是普通后台页，而是一个可以“换氛围”的桌面 AI 工作台。**

## 当前问题

### 1. 全局视觉层缺失

当前 `src/App.vue` 只是普通壳层，`src/style.css` 提供的是深色变量，但没有：
- 壁纸背景系统
- 半透明表面变量
- 前后景分层
- 统一的透明度、模糊、边框高光语言

### 2. 页面像原型，不像产品

- `Sidebar.vue` 是基础导航，没有悬浮感和桌面气质
- `ChatView.vue` 结构可用，但消息区、输入区、空状态缺少主舞台感
- `ActionsView.vue` / `AuditView.vue` / `SettingsView.vue` 都是简单列表和表单，没有统一卡片编排
- `RightPanel.vue` 只是硬切宽度的侧栏，不像半透明抽屉

### 3. 设置存在假保存

当前主题由 `useTheme.ts` 内存状态维护，没有从配置读取，也没有写回配置。重启后丢失。

### 4. LLM 测试存在假接入

当前设置页测试连接直接调用后端已保存配置，没有使用当前正在编辑的 provider / endpoint / model / api key 表单值。用户点击“测试连接”时，测试的不是眼前内容。

## 目标体验

### 全局体验

应用打开后应该表现为：
- 整个窗口有一张壁纸作为背景基底
- 主界面是半透明主容器，正文始终清晰可读
- 左侧导航、主聊天区、右侧抽屉、设置卡片都属于同一套半透明桌面层
- 切换主题色后，按钮、焦点、选中态和边缘高亮联动
- 切换壁纸后，整个应用氛围立即变化
- 调节透明度后，侧栏、主容器、卡片和输入区的透感同步变化
- 重新启动应用后，壁纸 / 主题色 / 主题预设 / 透明度仍然保留

### 设置体验

设置页应该从“堆表单”变为“外观 + 模型”的双卡片配置中心：
- 外观卡：主题预设、强调色、壁纸选择、透明度滑杆
- 模型卡：LLM 开关、provider、endpoint、model、api key、测试状态
- 保存与测试状态单独、清晰、可信

### 聊天体验

聊天页仍保持原逻辑，但视觉要更像主场景：
- 空状态更有品牌感
- 输入框更像桌面浮动输入条
- agent / user 消息区分更明显
- 选中态和 hover 更细腻
- 主内容仍然优先可读，不因为透明度而发灰或发虚

## 推荐实现方案

### 方案 A（采用）——全局半透明壳层 + 可持久化外观配置

#### 视觉系统

新增一套全局外观 token：
- 壁纸 ID
- 主界面透明度 `surface_opacity`
- 半透明面板背景色
- 面板边框高光
- 面板阴影
- 背景遮罩强度
- 主题色 glow / soft / ring

整体结构为三层：
1. **Wallpaper layer**：负责氛围图
2. **Ambient overlay layer**：负责暗化、染色、可读性
3. **Translucent app shell**：实际交互容器

首轮壁纸不走外部图片上传，而是使用**内置壁纸预设**。这些预设可以是 CSS 渐变、光斑、暗纹理组合，目标是有“壁纸感”，但不引入资源管理复杂度。

#### 设置能力

配置中新增外观字段，至少包含：
- `theme`
- `accent`
- `wallpaper`
- `surface_opacity`

其中 `surface_opacity` 存储为百分比整数，范围控制在 **35 - 88**，默认值建议为 **72**。这样设置页可以直接用滑杆展示，前端应用时再换算为 CSS 变量。

启动时前端从 `get_config` 读取并应用；修改后通过 `save_config` 持久化。

#### 测试连接

新增“按表单内容测试”的后端命令，前端测试时直接把当前 provider / endpoint / model / api key 传入，而不是依赖先保存。

## 组件级设计

### App Shell

`App.vue` 改为应用舞台：
- 最外层承载壁纸和氛围蒙层
- 中间放一个居中的半透明主容器
- 左右区域有统一圆角与边框语言
- 主容器透明度受 `surface_opacity` 控制

不改当前页面切换逻辑，只改结构 class 和样式层次。

### Sidebar

侧栏改成悬浮导航：
- 轻透明底色
- 顶部品牌区更精致
- 激活项使用 accent glow + 半透明选中底
- 折叠态仍保留，但宽度和图标对齐更精细

### ChatView

保留现有消息流与发送逻辑，增强：
- session bar 改成细颗粒工具条
- 空状态增加更强品牌层次
- 消息区更通透
- 用户消息气泡更像“半透明对话卡片”
- 输入区固定为主舞台底部半透明输入器

### RightPanel

改成半透明抽屉：
- 展开 / 关闭更柔和
- 边缘高光更明显
- 内容区支持更像 inspector panel 的节奏

### Actions / Audit

从简单列表改成信息卡片列表：
- 顶部有页面头部卡
- 列表卡带轻透明背景
- Mono 信息以更产品化方式呈现，不是裸行列表

### Settings

分成两个主卡：
1. **外观卡**：预设、强调色、壁纸、透明度
2. **模型卡**：provider 配置与连接测试

壁纸切换优先采用内置预设缩略图方案，而不是自由上传。原因：
- 范围更小
- 一致性更强
- 不引入文件选择与资源管理复杂度

首轮使用少量内置壁纸键值，例如：
- `aurora`
- `dusk`
- `lake`
- `mono`

## 数据与配置设计

### AppConfig 扩展

在现有配置结构中补充外观字段：
- `theme`: 主题预设 ID
- `accent`: 当前强调色
- `wallpaper`: 当前壁纸 ID
- `surface_opacity`: 当前半透明强度百分比

如已有 `theme` / `accent`，则保留并真正接入；新增 `wallpaper` 和 `surface_opacity`。

### useTheme 收口

`useTheme.ts` 不再只做内存 ref，而是负责：
- 接收外部配置初始化
- 应用 CSS variables / data attributes
- 修改时更新本地状态
- 供 Settings 和 App Shell 共享当前外观状态
- 根据 `surface_opacity` 推导面板背景和边框透明度

但保存动作仍由 Settings 明确触发，避免隐式写盘。

## 错误处理

### 外观保存失败

- 前端提示“保存失败”
- 保留当前编辑值，不静默回滚
- 不吞错误

### 壁纸值非法

- 后端或前端在应用前回退到默认壁纸
- 不让界面出现空背景

### 透明度值非法

- 对 `surface_opacity` 做范围校验
- 超出范围时回退到默认值 72
- 不让界面变成完全不透明或不可读

### LLM 测试失败

- 使用结构化结果返回：成功 / 失败、message、可选 model / latency
- 前端展示在设置页状态区
- 不影响当前表单内容

## 验证方式

### 视觉验收

1. 打开应用后可见壁纸背景，而不是纯色背景
2. 主容器、侧栏、右侧面板、设置卡片都具备统一半透明桌面感
3. Accent 修改后，按钮 / hover / focus / active 统一联动
4. 切换壁纸后，全局氛围明显变化
5. 调节透明度后，多个区域同步变化，但文字始终可读

### 功能验收

1. 修改主题预设、强调色、壁纸、透明度后保存，重启应用仍保留
2. Settings 中测试连接直接基于当前输入值，无需先保存
3. 保存 LLM 配置后，聊天仍能走现有 agent loop
4. 不改现有聊天、会话、审计、action 的业务行为

### 工程验收

1. 前端构建通过
2. Rust 构建通过
3. 不引入明显未使用代码
4. 改动主要限制在外观层、设置链路和相关配置边界

## 实施顺序

1. 扩展配置模型，补 `wallpaper`、`surface_opacity` 字段与测试命令输入
2. 打通前端 theme / wallpaper / opacity 初始化与保存
3. 建立全局半透明视觉 token 和 App Shell 背景层
4. 逐个重绘 Sidebar / Chat / RightPanel / Actions / Audit / Settings
5. 验证保存、恢复、测试连接与构建

## 风险与控制

### 风险 1：视觉改大了，影响可读性
控制：始终优先内容可读性，氛围层放在背景，不把正文做得过透明。

### 风险 2：设置页逻辑与展示耦合太深
控制：保持现有业务字段名，尽量只重组状态与样式，不重写业务流程。

### 风险 3：壁纸方案拖大范围
控制：首轮只做内置壁纸预设，不做上传、裁剪、持久化资源文件。

### 风险 4：透明度调节导致局部观感不一致
控制：透明度只收口到统一 token，不允许每个组件各自定义一套透明度。
